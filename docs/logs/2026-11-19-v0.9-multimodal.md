## Risk & Assumption Log
**RISK-20261119-V09-01 — GTFS shape too distant from stop**  
Mitigation: reject board/alight shape snap above 500 m; use stop geometry fallback.

**RISK-20261119-V09-02 — Browser transfer search explosion**  
Mitigation: capped first departures, downstream stops, transfer departures, labels per stop and global beam size.

**RISK-20261119-V09-03 — Fare reference mistaken for guaranteed price**  
Mitigation: "reference only" UI, eligibility warning, no fare scoring, unavailable for cross-region/unbounded cases.

**RISK-20261119-V09-04 — Shape dataset increases repository size**  
Mitigation: active shapes only, polyline encoding, deterministic shards so unchanged files remain stable across daily commits.

**DATA-20261119-V09-04 — Shape artifact verification**

**ISSUE-20261119-V09-01 — Initial Pages deployment artifact lookup**  
The first v0.9 Pages run uploaded its artifact successfully, but GitHub `deploy-pages` immediately returned "No artifacts named github-pages were found" while querying artifact metadata. This was a GitHub Actions/Pages handoff failure, not an XPLORE build/test failure.  
Mitigation: use the post-transit-build release evidence commit to trigger a fresh Pages deployment containing the generated shape shards.

**AUTO-20261119-V09-02 — Bot-commit deployment boundary**  
The transit workflow commits refreshed data using the repository `GITHUB_TOKEN`. GitHub does not recursively trigger other workflows from that bot-generated commit. A normal release/audit commit therefore provides the final Pages trigger after a schema-changing transit build. Production should eventually separate generated transit artifacts from source-control deployment to remove this coupling.
