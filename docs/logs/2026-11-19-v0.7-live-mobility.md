## Risk & Assumption Log

**RISK-20261119-V07-01 — Wrong realtime-to-schedule join**  
Likelihood: Medium without controls.  
Impact: High.  
Mitigation: exact trip ID + exact ordered stop sequence compatibility index.  
Status: MITIGATED BY DESIGN.

**RISK-20261119-V07-02 — Stale realtime treated as live**  
Likelihood: Medium.  
Impact: High.  
Mitigation: server max-age gate + client freshness gate; stale data cannot alter ranking.  
Status: MITIGATED.

**RISK-20261119-V07-03 — API credential exposure**  
Likelihood: High if called from static client.  
Impact: High.  
Mitigation: GitHub Actions secret only; browser receives compact generated JSON.  
Status: MITIGATED.

**RISK-20261119-V07-04 — Realtime workflow outage**  
Likelihood: Medium.  
Impact: Medium.  
Mitigation: failed refresh does not deploy and leaves last good snapshot in place; client eventually falls back when it ages out.  
Status: MITIGATED.

**RISK-20261119-V07-05 — GitHub Actions schedule jitter**  
Likelihood: Medium.  
Impact: Low/Medium.  
Mitigation: freshness is calculated from actual timestamps rather than assumed cadence.  
Status: ACCEPTED.

**RISK-20261119-V07-06 — Combined endpoint contract changes**  
Likelihood: Low/Medium.  
Impact: Medium.  
Mitigation: endpoint is repository-variable configurable; feed parsing fails closed.  
Status: ACTIVE.

## Activation Evidence — 2026-11-19

**QA-20261119-V07-04 — Strict compatibility build result**  
Current service date: 2026-11-19.  
Scheduled trips: 24,918.  
Strict realtime-compatible trips: 19,767.  
Exact-match coverage: 79.33%.  
Join rule: exact `trip_id` plus exact ordered `stop_id` sequence.  
Interpretation: approximately 79% of today's scheduled candidates can safely accept NTA v2 live evidence; the remainder must remain Scheduled.

**AUTO-20261119-V07-03 — Activation validation trigger**  
A narrow `push` trigger now validates the realtime credential/feed when the v0.7 adapter or compatibility index changes. Push validation builds the snapshot but deliberately does not deploy Pages, preventing a race with the normal site deployment. Scheduled/manual runs remain responsible for publishing refreshed realtime snapshots.

**DEC-20261119-V07-05 — No forced coverage**  
The 20.67% of current trips that do not pass the strict compatibility test are intentionally excluded from live enrichment. Coverage is allowed to be incomplete rather than using fuzzy joins.


**ISSUE-20261119-V07-02 — Push validation cancelled by Pages concurrency**  
Observed: the first post-merge Live Mobility push-validation run was cancelled before steps executed because it shared the `pages` concurrency group with the standard site deployment.  
Impact: no product/runtime regression; scheduled transit and v0.7 site deployment were unaffected, but credential/feed validation did not run.  
Fix: push validation now uses a separate `live-mobility-validation` concurrency group; scheduled/manual realtime deployments continue using `pages`.  
Status: FIX IMPLEMENTED / REVALIDATION REQUIRED.
